# 2026-11-16 工作日志

## 修复编译错误：syncConnectedState Unresolved reference

云打包报错 `Unresolved reference 'syncConnectedState'`（rtk-setting.kt:228 / :459）。

根因：UTS/uvue 的 `<script setup>` 编译成 Kotlin 后，函数声明**不提升**（不像 JS），必须先声明后使用。原 `syncConnectedState` 定义在文件末尾，但 `switchSource`/`onMounted` 更早调用了它。

修复：把 `syncConnectedState` 移到 `loadSource` 之后、`switchSource` 之前。同理把 `rememberDevice` 上移到 `refreshWifi` 之后，避免 `onConnectScanned` 先使用后定义。

## 新增网段自动扫描（自动发现 RTK 设备，不用手填 IP/端口）

需求：手动连接 RTK 时不知道 IP 和端口。归档目录里没有 IP/端口扫描插件（hmsscan=华为扫码、accessibility=无障碍、floatWebView=悬浮窗）。

方案：给 tdyb-rtk 插件新增网段扫描能力。

改动：
- `uni_modules/tdyb-rtk/utssdk/app-android/index.uts`：
  - 新增类型 `RtkScannedHost { ip, port }`
  - 新增常量 `RTK_COMMON_PORTS = [9000,15160,1212,4545,2010,8000,8001,8080]`（覆盖千寻/华测/中海达/南方常见端口）
  - 新增 `SubnetProbeRunnable`：单 IP 串行探所有常见端口（300ms 超时）
  - 新增 `scanSubnetForRtk(subnet, onHit, onComplete)`：扫网段 1~50 号 IP，命中回调 onHit，全扫完 onComplete。用 `number[]` 数组做计数器（引用类型），避免闭包捕获可变局部变量的 UTS 限制。
  - 新增 `currentSubnet()`：从 WiFi IP 推导网段前三段。
- `pages/rtk-setting/rtk-setting.uvue`：
  - WiFi/TCP 模式加「自动扫描」卡片：`onScanSubnet()` 触发扫描，`onConnectScanned()` 连接扫描到的设备，结果列表显示为可点设备。

关键点：扫描回调都经 `postToUi` 回主线程，计数器自减串行安全。
