# 2026-11-17 工作日志

## RTK 设置页体验优化（4 个问题修复）

1. **返回再进入切回蓝牙**：`mode`（连接方式）之前是页面局部 ref，默认 `'bluetooth'`，页面销毁重建后又回到蓝牙。修复：连接方式持久化到 storage `rtkConnMode`，`loadSource()` 恢复，`switchMode()` 保存。

2. **不可连接设备变灰**：设备清单里所有设备都显示「连接」。修复：`onConnectPreset()` 内部判断 `!device.connectivity` 则 toast 提示并 return；模板里不可连接的设备显示「不可连接」+ 灰色「—」按钮（新增 `device-badge-disabled`、`device-connect-disabled` 样式）。

3. **删除「连接当前 WiFi 识别设备」按钮**：删除模板 `hasMatched` 按钮 + script 里 `hasMatched`/`matchedLabel` 计算属性 + `onConnectMatched()` 函数。保留 `matchedPreset`/`matchedName`/`wifiMatchText`（用于「识别到 XX」提示和「当前 WiFi」标记）。

4. **连接后返回不显示连接信息**：根因是 mode 未持久化导致显示错乱。修复：`syncConnectedState()` 里根据 `isBluetoothConnected()`/`isTcpConnected()` 实际状态**强制纠正 mode**（蓝牙连接→mode='bluetooth'，TCP 连接→mode='wifi'），并新增 `readSavedLabel()` 从 `rtkDevice` storage 恢复具体设备标签（如 "设备名 (IP:端口)"），避免只显示通用「WiFi TCP 设备」。

关键点：UTS 函数声明不提升，`readSavedLabel` 必须定义在 `syncConnectedState` 之前。

## 返回 RTK 设置页「数据丢失 / 像没连接」修复（数据驱动连接状态）

- 现象：返回再进入 RTK 设置页，约 5 秒后才恢复连接信息（定位数据其实一直在流）。
- 根因：`connected` 是页面级状态，返回重建后只靠 `isBluetoothConnected()`/`isTcpConnected()` 实时查 socket。但 socket.isConnected() 在 App 前后台切换/TCP 半关闭时可能短暂误报 false；且 `onNmea` 只更新 `fix` 不更新 `connected`，导致即使数据在流也显示「未连接」，要等下一次 GGA（约 5 秒慢推流）才恢复。
- 修复（三层保障）：
  1. `syncConnectedState()` 增加 `lastFixIsFresh()` 兜底：socket 查询不到但最近 10 秒内仍在收 GGA，就按上次记住的连接方式强制显示已连接。
  2. `onNmea()` 收到有效 GGA 时直接驱动 `connected=true`（数据是最可靠的连接凭证），并纠正 mode / 补 connectedLabel。
  3. `lastFixIsFresh()` 阈值放宽到 10 秒（部分 RTK 是 5 秒/条慢推流，3 秒会误判）。
- 新增 import：`getLastFixAt`。
