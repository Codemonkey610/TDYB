# 新壳接入说明（uni-app x + 高德定位）

## 0. 一句话

新壳 = **一个全屏 `<web-view>` + 一个定位桥**，通信走 **uni-app x 官方标准通道**
（签名以 HBuilderX 自带 `builtin-dts/.../uni-app-x/types/native/IUniElement.d.ts` 为准）：

- 页面 → 壳：`window.__uniapp_x_postMessage({ data: { method, message, key } })`
  —— 这个全局是 web-view 注入到网页里的原生桥，**不需要引 `uni.webview.js`**；
  壳侧 `<web-view @message="...">` 收到的 `event.detail.data` 是 **`Array<UTSJSONObject>`**，
  数组里每一项就是网页 post 的那个 `data` 对象。
- 壳 → 页面：`element.evalJS('window["key"] = "<JSON字符串>"')`，
  注意官方签名是 `evalJS(js): void` —— **没有返回值、没有回调**，所以壳不能主动从网页取数据。

前端已按官方标准改造（真实仓库 `D:\chen\SM\SMCJ\frontend`，不是复制过来的 `TDYB_VUE`）。
**壳里没有任何注入脚本、没有轮询**——之前那套 shim + evalJs 轮询的兜底方案已经删掉，
因为在 `evalJS` 无返回值的前提下它根本不可能工作。

```
Vue（WebView 里）                                     壳（uni-app x）
──────────────                                      ──────────────
postMessageToApp({method,message,key})
   │ window.__uniapp_x_postMessage({data: 对象})       ← web-view 注入的原生桥
   ▼
<web-view @message>  event.detail.data: Array<UTSJSONObject>
   ▼
dispatch.uts  →  location.uts  →  AMap SDK
   │
   ▼
window[key] = "…JSON…"  ◄── evalJS('window["key"]=…')   ← 单向，够用
   │ setter 触发
   ▼
success(res) / fail(err)
```

> 真机日志看到 `[TDYB] web-view 加载完成` + 点定位有回传 = 通道正常。
> 点定位没反应、`isInApp()` 为假，说明 `__uniapp_x_postMessage` 没注入（见第 6 节排查）。

## 2. 跑通步骤

### 2.1 改页面地址
`utils/config.uts` → `FRONTEND_URL`（当前配置 `http://36.248.211.159:8017/`）。
真机必须能访问这个地址；页面是 history 路由，Nginx 要 `try_files $uri /index.html`。

### 2.2 包名与高德 key（必做，否则 errorCode=15）

**包名：`com.kingtop.xasjcj`**（沿用旧壳，写在 `manifest.json` 的 `app-android.distribute.packagename`）。

沿用旧包名的原因：同包名 + 同一张云证书 → 新包可直接覆盖升级旧 App，
而且旧的高德 key（按 `com.kingtop.xasjcj` 申请的）大概率继续有效，不用重新申请。
代价是**不能和旧 App 同时装在一台手机上**（同包名只能装一个）。

> 换包名 = 必须重新申请高德 key + 旧设备只能卸载重装。确定要换就现在换，别等发版。

**SHA1（云证书）**：DCloud 开发者中心 → 我的应用 → 应用详情 → Android 平台信息 → 云端证书信息，里面有 SHA1。
拿不到的话，先随便打一次云打包，然后对 APK 执行：

```
keytool -printcert -jarfile your.apk
```

1. 高德控制台新建 key，平台选 **Android**，包名填 `com.kingtop.xasjcj`，SHA1 填上面拿到的值。
2. 把 key 填进 `uni_modules/tdyb-amap-location/utssdk/app-android/AndroidManifest.xml`
   的 `com.amap.api.v2.apikey`。
3. 改完必须**重新打自定义基座**，key 是编进 manifest 的。

> 也可以把 key 放 `utils/config.uts` 的 `AMAP_KEY`，壳运行时 `setApiKey` 覆盖；
> 但 manifest 方式最稳，推荐 manifest。
>
> **打包后在 HBuilderX 打包界面确认一下"包名"显示的是 `com.kingtop.xasjcj`**，
> 如果显示的是 `uni.UNI3ABC950` 之类的默认值，说明这个字段没被识别，告诉我我换写法。

### 2.3 确认 SDK 依赖能拉到

## 3. 与 Vue 的接口对照

| Vue 调用（`bridge/location.ts`） | 壳处理方法 | message 里读什么 | 回写 |
|---|---|---|---|
| `getPreciseLocation({type,geocode,success,fail})` | `handlePrecise` | `type`/`coordType`、`geocode` | 单次定位对象 |
| `getLocationQuickly({type,geocode,...})` | `handleQuick` | 同上 | 单次定位对象（允许缓存） |
| `startGetLocationService({interval,success,fail})` | `handleStart` | `interval`、`coordType`、`needAddress` | **每来一条定位回写一次** |
| `closeGetLocationService()` | `handleClose` | — | `"关闭成功"` |
| `openLocationSetting()` | `handleOpenSetting` | — | `{success:true}` |
| （旧壳保留）`setLocationMode` / `getLocationMode` | `setMode` / `getMode` | `mode` | `{success:true}` / 模式串 |

回写对象（对齐 `normalizeLocation`，顶层必须有 `longitude`/`latitude`）：

```json
{
  "longitude": 118.26, "latitude": 24.67,
  "altitude": 12.3, "accuracy": 8.5,
  "speed": 0.3, "bearing": 90,
```

## 4. 节奏控制（你要的"传几秒拿一次"）

- 前端在 `startGetLocationService({ interval: 1000 })` 里传毫秒数；
- 壳钳制到 **1000~10000ms**，直接作为高德 SDK 的采样间隔；
- 壳再兜一层：距上次回传 < `interval*0.8` **且**位移 < 0.5m 时丢弃，避免桥被淹；
- 前端 `useAutoRecord` 自己还有 1s/0.5m 节流——**两层节流互不冲突**，前端拿到的仍然是自己要的频率。

## 4.1 后台持续定位（锁屏/切后台也不断）

需要三件事同时成立，缺一个都会被系统掐掉：

| 条件 | 代码里怎么做的 | 用户要做什么 |
|---|---|---|
| 定位权限「始终允许」 | 首次 `startGetLocationService` 弹窗引导 → `requestBackgroundPermission()` | Android 11+ 跳到应用详情页，手动把定位改成"始终允许" |
| 前台服务 + 常驻通知 | `enableBackground()` 调高德 SDK `enableBackgroundLocation()`；停止时 `disableBackground()` | 下拉通知栏能看到「正在后台持续定位」，**不要划掉** |
| 忽略电池优化 | `isIgnoringBatteryOptimizations()` 检测，未开则弹一次「去设置」 | 允许忽略电池优化 |
| 国产 ROM 自启动 | 做不到代码强制 | 华为/小米/OPPO/vivo 需在手机管家里允许自启动、后台运行 |

实现位置：[插件 index.uts](uni_modules/tdyb-amap-location/utssdk/app-android/index.uts) 的「后台定位 / 保活」段 + [location.uts](bridge/location.uts) 的 `ensureBackgroundPermission` / `ensureBatteryOptimization`。

**已知风险**：`targetSdkVersion=34` 对前台服务类型要求最严，如果高德 6.4.3 的服务的 `foregroundServiceType` 不兼容，`enableBackgroundLocation` 可能抛 `SecurityException`。真机日志出现「开启后台定位失败」时，把 `manifest.json` 的 `targetSdkVersion` 降到 `33` 即可（内部应用不受上架限制）。

## 6. 排查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 点定位无任何反应 | 网页没拿到 `__uniapp_x_postMessage`，`isInApp()` 为假 | 页面控制台执行 `typeof window.__uniapp_x_postMessage`，为 undefined 说明该 web-view 版本没注入桥 |
| `@message` 收不到 | 网页发的是 JSON 字符串而不是对象 | 必须 `postMessage({data: 对象})`；壳侧 `detail.data` 是 `Array<UTSJSONObject>` |
| 定位返回 `errorCode=15` | key 包名/SHA1 不匹配 | 重新申请 key + 重打基座 |
| 定位返回 `errorCode=12` | 权限被拒 | 系统设置里允许定位 |
| 长按无响应/白屏 | 页面地址错 / cleartext 被拦 | 用 `https`，或确认 manifest 的 `usesCleartextTraffic` |
| 刷新后 404 | SPA history 没回退 | Nginx `try_files $uri /index.html` |
| 自动记录一个点都不出 | 精度门限 | 已把 `useAutoRecord` 默认改 30m，见第 7 节 |
| 地图瓦片空白 | 页面是 https 但瓦片是 http | 统一协议，别混用 |
| 后台定位被掐 | 没给「始终允许」/ 被 ROM 清理 | 见 4.1，另需手动开自启动 |

## 7. 前端改了 4 处（位置：真实仓库 `D:\chen\SM\SMCJ\frontend`）

> `D:\chen\TDYB\TDYB_VUE\frontend` 只是副本，已同步到与仓库一致，以仓库为准。

**通信层（本次按官方标准改造）**

1. `src/bridge/location.ts` — `postMessageToApp` 改为调用 `window.__uniapp_x_postMessage({ data: postMsg })`，
   发的是**对象**（不是 JSON 字符串）；`isInApp()` 识别 `__uniapp_x_postMessage`；
   旧 App-Plus 的 `__dcloud_weex_postMessage` 保留兜底；
   回调改成"先挂 setter 再发送"，避免壳回写比发送返回更快导致丢消息。

**业务层（不修则自动记录一条都出不来）**

2. `src/bridge/location.ts` — `isFixedSolution` 增加 `gps/network/amap` 状态白名单
   （原来只认 `fixed/固定解`，手机定位状态是 `gps`，直接被判为"非固定解"）。
3. `src/bridge/location.ts` — `startGetLocationService` 参数类型增加
   `interval/coordType/needAddress`，透传给壳。
4. `src/composables/useAutoRecord.ts` — `maxAccuracy` 默认 `0.05` → `30`（米），
   并在启动时把 `interval` 传给壳。

> 将来接回 RTK 时：`useAutoRecord({ maxAccuracy: 0.05 })` 显式传即可，逻辑不用再动。

## 8. 已经踩过的 UTS 坑（都改完了，留作参考）

UTS 的解析/类型规则和 TS 不一样，这次实际撞到并修掉的：

| 报错 | 原因 | 正确写法 |
|---|---|---|
| `Unexpected token` 在 `data is Array<any>` | `is` 只能用在类型谓词声明处，不能写进表达式 | `Array.isArray(data)` / `instanceof UTSJSONObject` |
| `Function3 ... but Function2 was expected` | 这版 `UTSAndroid.requestSystemPermission` 回调是 **2 个参数** `(allRight, granted)` | 去掉第三个 `denied` |
| `actual type is 'Int', but 'Long' was expected` | `AMapLocationClientOption.setHttpTimeOut` 要 **Long** | `timeout.toLong()` |
| Java `float/long/int` 不能隐式转 `number` | UTS 的 `number` 就是 Double | `getAccuracy().toDouble()` 等显式转换 |
| `evalJs` 带回调编译不过 | 官方签名是 `evalJS(js): void`，无返回值 | 只能单向执行；上行靠网页 `postMessage` |

> 还没验证到的两处（如果报错再改）：`class TdybAmapListener implements AMapLocationListener`
> 的实现写法、`AMapLocationClient.enableBackgroundLocation(int, Notification)` 的签名。
